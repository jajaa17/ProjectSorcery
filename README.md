# Project Sorcery

**A 2D stickman arena fighter about cursed techniques, domain expansions and Black Flashes, built in Unity 6.**

Stick figures, ink-black impact frames, screen-shattering domain clashes. 71 playable sorcerers and curses (plus one raid boss), local and online multiplayer, gamepad support, and an AI that actually fights back.

> Fan-made and non-commercial in spirit. Project Sorcery is *inspired by* the anime and manga *Jujutsu Kaisen* by Gege Akutami. It uses no official names, art, audio or assets: every character, technique and domain has an original name, and everything you see and hear is generated by code at runtime. Not affiliated with or endorsed by the original creator, Shueisha, or MAPPA.

## Features

**Fighting**
- 71 playable fighters + 1 raid boss, each with a unique technique, 4-skill kit, passives and their own movement style (martial artists, brutes, floaty casters, feral curses, wrestlers, swordsmen…)
- **Domain Expansion** for all 17 domain users, with chants, barrier animations and unique sure-hit effects
- **Domain clashes**: 2-way *and* 3-way (1v1v1) clashes with anime-style portrait cut-ins and button mashing
- **Black Flash**: rhythm-timed crits with full-screen ink-inversion impact frames and their own sound design
- Reverse Cursed Technique healing, Simple Domain, Infinity-style barriers, heavenly restrictions (no cursed energy, invisible to sure-hits, monstrous bodies), adaptation, shikigami, binding vows and more
- Smooth, spring-driven procedural animation: each hit lands with weight, heavy hits feel heavy

**Modes**
- **Versus**: 1v1, 2v1, 2v2 and 1v1v1 free-for-all, any mix of humans and CPUs
- **CPU difficulties**: Easy, Medium and Hard (the AI reads threats, combos, times Black Flashes, expands and clashes domains)
- **Survival**: endless waves of sorcerers and curses, with elites and recovery between waves
- **Calamity Raid**: you (plus a friend and/or CPU allies) against the King of Calamity in his Heian-era true form. Three phases, a barrier-less domain, a summoned divine general. Very overpowered, but beatable.
- **Training**: infinite cursed energy and a dummy you can set to block
- **Online**: host or join over LAN / the internet (lockstep netcode, 2 to 4 players)

**Presentation**
- Procedural VFX: cursed-energy auras, slashes, beams, shockwaves, impact frames, camera shake and zoom
- Procedural audio: every punch, slash, chant and domain drone is synthesized at runtime, plus generated music
- 7 hand-painted-by-code arenas (one is raid-only)
- Clean, low-distraction HUD
- Settings for audio, graphics quality, VFX intensity, screen shake, FPS cap, V-Sync, fullscreen/resolution, input delay and more

**Controls**
- Keyboard (2 players on one keyboard) and up to 4 gamepads (Xbox, PlayStation, Switch Pro… via Unity's Input System)

## Getting started (play from source)

1. Install **Unity 6** (tested with `6000.0.58f2`; any Unity 6000.0.x should work) via Unity Hub.
2. Clone this repo and open the folder in Unity Hub (**Add > Add project from disk**).
3. On first open the editor sets everything up automatically (scene, build settings, input handling). If anything looks off, run **Project Sorcery > Setup Project** from the menu bar.
4. Open `Assets/ProjectSorcery/Scenes/Main.unity` and press **Play**.

There are no art, audio or prefab assets to import. The whole game (menus, fighters, arenas, VFX, sound and music) is built from code when it starts.

> If Unity asks to restart because of the Input System backend, click **Yes**. The project uses "Both" (new Input System + legacy) so gamepads work everywhere.

## Building a release (e.g. for itch.io)

1. **File > Build Profiles** (or Build Settings), choose **Windows** (or macOS / Linux).
2. Make sure `Main` is the only scene in the list (the setup step does this for you).
3. **Build** into an empty folder, e.g. `Builds/Windows`.
4. Zip the *contents* of that folder and upload it to itch.io as a downloadable (mark it as a Windows/macOS/Linux executable).
   Optional: use [butler](https://itch.io/docs/butler/) for incremental updates: `butler push Builds/Windows yourname/project-sorcery:windows`.

## Controls

| Action | Keyboard P1 | Keyboard P2 | Gamepad |
|---|---|---|---|
| Move / crouch | `A` `D` / `S` | Arrows | Left stick / D-pad |
| Jump | `W` / `Space` | `Up` | A / Cross |
| Light attack | `F` / `J` | `Num1` / `,` | X / Square |
| Heavy attack | `G` / `K` | `Num2` / `.` | Y / Triangle |
| Block | `H` / `L` | `Num3` / `/` | RB / R1 |
| Dash | `Left Shift` | `Num0` / `Right Shift` | B / Circle |
| Skill 1 / 2 / 3 | `R` `T` `Y` (or `U` `I` `O`) | `Num4` `Num5` `Num6` (or `K` `L` `;`) | LB, LT, R3 (or right stick) |
| Ultimate / Domain | `V` / `P` | `Num+` / `'` | RT / R2 |
| Pause | `Esc` | `Esc` | Start |
| Menu back | `Esc` | `Backspace` | B / Circle |

The alternate keys in brackets are for solo play. They switch off automatically when a second keyboard player joins.

**Universal techniques**
- `Down + Light` sweep, `Down + Heavy` launcher
- **Black Flash**: land a light hit, then press Heavy *in rhythm*. Nail the window for a critical hit with a 2.5× distortion.
- **Hold Block + Down**: Reverse Cursed Technique (heal, if your fighter has it). Inside an enemy domain this becomes **Simple Domain** and reduces the sure-hit.
- **Block + Dash while being juggled**: Burst out of a combo
- **Hold a skill button**: chant to empower the technique (if it's chantable)
- **Domain clash**: when two or three domains collide, mash your attack buttons to win the refinement battle

## Online multiplayer

1. One player picks **Play > Online > Host**. Everyone else enters the host's IP and presses **Join**.
2. Same network? Use the host's local IP (for example `192.168.1.23`).
3. Over the internet, either forward **UDP port 7777** on the host's router, or everyone installs a free virtual LAN like **Tailscale**, **ZeroTier** or **Radmin VPN** and uses the IP it shows.
4. Allow the game through the firewall when Windows asks.
5. Everyone must run the **same build** (the lobby checks this).

The netcode is deterministic lockstep: only button presses are sent, the simulation runs at a fixed 60 Hz on every machine, and checksums catch any desync. If it feels choppy, raise **Input Delay** in Settings.

## Project layout

```
Assets/ProjectSorcery/
  Editor/            one-click project setup (scene, build + player settings)
  Resources/         the only non-code asset: an additive glow shader
  Scripts/
    Core/            boot (GameRoot), deterministic Match simulation, settings, RNG, balance knobs
    Fighter/         fighter state machine, damage model, procedural stick rig and poses
    Abilities/       ability building blocks (projectile, beam, strike, burst, summon, zone, buff, counter, domain…)
    Combat/          projectiles, beams, minions/shikigami, zones
    Domain/          domain expansion, N-way clashes, sure-hit effects, domain visuals
    Data/            the roster: every character and kit, one file per faction
    Modes/           Versus, Training, Survival, Raid
    AI/              CPU brain and difficulty profiles
    VFX/             particle pools, impact frames, camera rig, arenas, procedural textures
    Audio/           runtime synthesizer, sound bank, procedural music
    UI/              uGUI built in code: menus, character select, HUD, cut-ins
    Net/             UDP lobby and lockstep netcode
    Input/           keyboard, gamepad and merged devices
Tools/Simulator/     headless simulator for tests and balance (runs the real gameplay code)
```

The simulation (`Match.SimTick`) is fully deterministic and separate from presentation, which makes online lockstep, replays and headless testing possible.

## Headless simulator and balance

`Tools/Simulator` compiles the real gameplay scripts against small Unity stand-ins and runs thousands of CPU-vs-CPU matches in seconds. You only need the [.NET 8 SDK](https://dotnet.microsoft.com/download).

```bash
cd Tools/Simulator
dotnet run -c Release -- all          # determinism, smoke test of every fighter, modes, domain clashes
dotnet run -c Release -- balance 40   # Hard-vs-Hard win-rate survey per fighter
dotnet run -c Release -- tune 10 80   # auto-tune per-fighter damage/toughness multipliers
```

The numbers in `Scripts/Core/Balance.cs` (`Tuning`) come from the tuner. In the current table every fighter lands between roughly 40% and 60% win rate in Hard-AI duels. CI runs `all` on every pull request.
